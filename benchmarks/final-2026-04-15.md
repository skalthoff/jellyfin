## Optimizations Applied

### Phase 1: Database Indexes
- ItemValueMap(ItemId, ItemValueId) — enables artist/genre filtering via index
- BaseItem(TopParentId, Type, SortName) — covers music listing queries
- BaseItem(Type, TopParentId, DateCreated, SortName) — covers recently-added
- UserData(UserId, ItemId) and (UserId, Played, LastPlayedDate)

### Phase 2: Query Strategy
- Adaptive AsSplitQuery/AsSingleQuery based on query pattern
- Filtered Include on UserData — loads only requesting user's play state

### Phase 3: Materialized Artist Query (THE KILL SHOT)
- Rewrote WhereReferencedItemMultipleTypes to pre-resolve lookup chain
- Eliminated O(n*m) correlated subquery, replaced with 3 fast queries + IN clause
- Impact: 503ms to 11ms (45x)

### Phase 4: DTO Pipeline
- Batch artist lookups in DtoService (1 query instead of N per item)
- Eliminates 200-400 extra DB roundtrips per API response

### Phase 5: Library Scan
- Eliminated FFProbe process spawn for local audio files
- Uses ATL in-process for duration, bitrate, codec extraction
- Eliminates 500k process spawns during initial scan

### Phase 6: SQLite Tuning
- 64MB cache (8x default)
- 256MB mmap for memory-mapped I/O
- WAL mode, synchronous=NORMAL, temp_store=MEMORY
